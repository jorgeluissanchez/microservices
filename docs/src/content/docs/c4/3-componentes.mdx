## Microservicio Auth

<Image src={authImg} alt="A bird." width="2000%" />

### Claves de Auth

* **Gestor de Seguridad:** Es el componente central para la **verificación de credenciales**, aplicando algoritmos de _hashing_ para proteger las contraseñas.
* **Emisor/Validador de Tokens:** Es el componente que tiene la responsabilidad exclusiva de **firmar** los JWT durante el _login_ y de **validarlos** (firma y expiración) en las peticiones de otros servicios.
* **Doble Flujo:** El diagrama detalla dos flujos críticos:
    1.  **Inicio de Sesión (Login):** Interacción entre la _Aplicación Web_, el _Controlador_, el _Gestor de Seguridad_ y el _Emisor de Tokens_.
    2.  **Validación de JWT (Servicio a Servicio):** El _Microservicio payment_ usa el _Cliente de Servicios (Interno)_ para **pedir una validación** al _Emisor/Validador de Tokens_ antes de otorgar acceso o procesar la petición.
* **Repositorio de Usuarios:** Únicamente es consultado para **obtener el _hash_** de la contraseña o los datos básicos del usuario, no para la lógica de validación de tokens.

## Microservicio Payment

![Diagrama de Componentes](/diagrams/payment.png)

### Claves de Payment

* **Separación de Responsabilidades:** La lógica de negocio (_Gestor de Lógica de Negocio_) está separada del acceso a datos (_Repositorio de Persistencia_) y de la comunicación externa.
* **Controlador de Suscripciones:** Actúa como _guardián_, asegurando que la identidad del usuario se **valide primero** a través del _Cliente de Autenticación (auth)_ antes de proceder con cualquier acción.
* **Cliente de Pasarela de Pago:** Es el único componente que conoce y utiliza el SDK/API para interactuar con el **Sistema de Pago Externo**.
* **Persistencia Local:** Solo el _Repositorio de Persistencia_ escribe en la **Base de Datos _payment_db_**, garantizando la coherencia de los datos de suscripción.


## Microservicio Reservation

### Componentes internos:

- **ReservationController:** gestiona `/reservation/create`, `/reservation/cancel`.

- **ReservationService:** coordina la lógica de negocio.

- **ReservationRepository:** acceso a PostgreSQL.

- **KafkaConsumer:** escucha eventos de pago y actualiza reservas.

### Flujo interno:

1. Usuario solicita una reserva.

2. Se valida el usuario (Auth).

3. Se solicita pago (Payment).

4. Si el pago es exitoso → se confirma la reserva.

### Puntos clave:

- Orquesta el flujo completo entre microservicios.

- Depende de los resultados del sistema de pagos y autenticación.

## API Gateway

### Componentes internos

- **Controllers:** manejan rutas `/auth`, `/payment`, `/reservation`.

- **Proxy Layer:** reenvía solicitudes HTTP hacia cada microservicio.

- **Validation & Error Handling:** valida datos entrantes y captura errores globales.

### Puntos clave:

- No contiene lógica de negocio.

- Centraliza la autenticación y validación inicial.

- Permite desacoplar el frontend de la estructura interna.
